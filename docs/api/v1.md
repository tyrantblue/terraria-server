# API v1 参考（给前端）

**2.0.0 起这是唯一的接口面**：旧的 `/api/*` 资源路由已删除（返回 404）。
完整的变更与迁移对照见 [`CHANGELOG.md`](CHANGELOG.md)。

约定：

* 基础地址 `https://terraria-api.tyrantblue.xyz`（或直连 `http://<VPS>:8080`）。
* 请求/响应都是 JSON；上传世界用 `multipart/form-data`。
* 成功**直接返回资源本体**，不再包 `{"success": true}`。
* 失败统一：

  ```json
  { "detail": "player not online: foo",
    "error": { "code": "not_found", "message": "player not online: foo", "details": {} } }
  ```

  `code` 是稳定字符串（`bad_request` / `not_found` / `conflict` / `forbidden` /
  `validation_failed` / `upstream_failed` / `payload_too_large` /
  `insufficient_storage` / `console_unavailable` / `console_busy` /
  `console_timeout`），前端按它分支即可；`details` 可选。
* 可以带 `X-Client-Version: <面板构建版本>`，服务端会在响应里原样回显（排障用）。

## 1. 握手与元信息

### `GET /api/meta`
面板启动时调一次。

```json
{
  "api_version": "2.0.0",
  "min_client_version": "1.4.0",
  "server_version": "1.4.5.8",
  "capabilities": ["server.status", "world.metadata", "config.password_masked",
                   "console.audit.persistent", "server.log_health", "server.metrics",
                   "meta.handshake", ...],
  "deprecations": [],
  "links": { "openapi": "/openapi.json", "docs": "/docs", "changelog": "https://..." }
}
```

* `api_version` **遵循 semver**：patch = HTTP 契约没变（内部修复/新定时任务/新事件类型），
  minor = 有新增（用 `capabilities` 判断），major = 有删除/变更。
  **只有 `min_client_version` 高于面板版本才是"必须升级"的硬条件**，
  不要因为 patch 差异弹提示。
* 2.0.0 起 `min_client_version` 是 `1.4.0`：旧接口已删除，更旧的面板必须升级。
* `capabilities` 用来做功能开关（老后端没有的新能力别渲染）。
* `deprecations` 字段仍然存在，但**恒为 `[]`**（旧接口已经删完，没有可弃用的东西了）。
* `timezone` / `capabilities` 之外的字段都可能为 null，渲染时注意空值。

### `GET /api/health`

```json
{ "status": "ok", "service": "terraria-api" }
```

## 2. 服务器状态

### `GET /api/v1/server`
**一次拿全**，取代旧版「`/api/server/status` + 7 个查询型 POST + `/api/world/list`」。

```json
{
  "running": true,
  "version": "1.4.5.8",
  "port": 7777,
  "max_players": 255,
  "time": "4:20 PM",
  "seed": "3.3.1.0.1269458679",
  "motd": "Fly to the sky…Fire bird! Join the RED TEAM, PLZ!!!",
  "players": {
    "online": 2,
    "max": 255,
    "players": [
      { "name": "ユノの犬", "ip": "203.0.113.10", "port": 26557 },
      { "name": "CTQ", "ip": "198.51.100.30", "port": 44176 }
    ]
  },
  "world": { "file": "gogogo.wld", "name": "gogogo", "size": 12300762,
             "modified_at": 1789000000.0, "active": true },
  "config": { "maxplayers": "255", "motd": "...", "port": "7777", "world": "/worlds/gogogo.wld",
              "password": "••••••" },
  "password_set": true
}
```

字段可能是 `null`（服务端刚重启、控制台暂时读不到）。`time`/`players` 最多有 3 秒缓存，
`version/port/max_players/seed/motd` 属于静态字段（服务端重启或改过配置才会刷新）。

**敏感字段不回显明文**：`config.password` 永远是掩码 `••••••`（未设密码时是 `""`），
是否已设置看 `password_set`。改密码请用 `PUT /api/v1/config`（见 §5）。

### `POST /api/v1/server/actions`
```json
{ "action": "save" }      // 或 "settle"
```
→ `{"ok": true}`

### `POST /api/v1/server/restart` → **202**
保存 → 关服 → 等待重新监听，全程后台执行：
```json
{ "operation_id": "8f3c1a9b2d4e", "state": "pending", "kind": "server.restart" }
```

### `POST /api/v1/server/time`
```json
{ "phase": "noon" }       // dawn | noon | dusk | midnight
```
→ `{"phase": "noon", "time": "12:00 PM"}`

### `GET /api/v1/metrics?minutes=60`
资源与在线人数曲线（后端每 `METRICS_INTERVAL_SECONDS` 采一个点，默认 60 秒；
内存保留 `METRICS_RETENTION_POINTS` 个点，默认 1440 = 24 小时）。

```json
{
  "interval_seconds": 60.0,
  "retention_points": 1440,
  "window_minutes": 60.0,
  "latest": { "ts": 1789700000.0, "cpu_percent": 12.5, "cpu_cores": 2.0,
              "memory_bytes": 66674688, "memory_limit_bytes": null,
              "disk_free_bytes": 21474836480, "disk_total_bytes": 53687091200,
              "players_online": 2 },
  "points": [ { "ts": 1789699940.0, "...": "同上" } ]
}
```

* `points` 按时间**升序**；`?minutes` 上限 1440。
* 字段可能为 `null`：非 Linux/cgroup 环境拿不到 CPU/内存，`memory_limit_bytes`
  为 `null` 表示容器没设内存上限。画曲线时空点跳过即可。
* 采样点只在内存里（API 重启后从零开始）——这是近期曲线，不是长期监控存储。
* 读哪些值：CPU 是「累计 CPU 时间」的差值，已按容器可用核数折算（100% = 吃满分配
  的核）；`cpu_cores` 就是那个折算基数（来自 `cpu.max` 配额或 `cpuset`）。
* `METRICS_INTERVAL_SECONDS=0` 可以关掉采样，此时 `points` 恒为空数组。

## 3. 玩家与广播

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/players` | `{online, max, players:[{name,ip,port}]}` |
| POST | `/api/v1/players/{name}/kick` | 玩家不在线 → **404** `not_found` |
| POST | `/api/v1/players/{name}/ban` | 同上；底层是控制台 `ban` |
| DELETE | `/api/v1/players/{name}/ban` | 从 `banlist.txt` 移除；不在名单 → **404** |
| GET | `/api/v1/bans` | `{bans:[...], source, exists, note}` |
| POST | `/api/v1/broadcast` | `{"message":"..."}` → `{"ok":true}` |

`{name}` 需要 URL 编码（玩家名可能含空格/日文，例如 `%E3%83%A6...`）。

关于封禁：原版控制台**只有 `ban` 没有 `unban`**，而且只会给「当前在线」的玩家写名单；
`banlist.txt` 在第一次封禁之前不存在（此时 `exists=false`、`note` 会说明）。
`DELETE` 是按行改写文件，因此可以移除不在线的历史封禁。

## 4. 控制台

### `GET /api/v1/console?tail=200` 或 `?since=<cursor>`

```json
{
  "lines": [
    { "offset": 524288, "ts": 1789636035.0, "kind": "player_join",
      "text": "[2026-09-17 17:07:15] : ユノの犬 has joined." },
    { "offset": 524310, "ts": 1789636035.0, "kind": "chat",
      "text": "[2026-09-17 17:07:15] : <ユノの犬> 加油" }
  ],
  "cursor": 524340
}
```

`ts` 是由 `start.sh` 打在行首的 `[YYYY-mm-dd HH:MM:SS]` 解析出来的 epoch（秒）；
旧日志没有时间戳时为 `null`。`text` 保留原始内容（含时间戳前缀）。

* `kind`：`player_join` `player_leave` `connect` `disconnect` `boot` `chat`
  `world_save` `startup` `error` `prompt` `output` `blank`。
  面板可直接按 `kind` 上色/过滤，不必自己正则。
* **增量拉取**：把上一次的 `cursor` 作为 `since` 传回来，只拿新行。
* 服务端内部使用的哨兵回显已被过滤，不会出现。

### `WS /api/v1/console/stream`
连接后先收到最近约 100 行**历史回放**（`console.line` 帧），然后是
`{"type":"hello","cursor":N}`，之后持续推送新行：

```json
{ "type": "console.line", "offset": 524340, "ts": 1789636035.0, "kind": "chat", "text": ": <CTQ> hi" }
{ "type": "hello", "cursor": 524341 }
```

* **`offset` 在回放和实时帧里是同一个语义**：真实的行起始字节偏移，来自同一个日志文件。
  可以直接拿它当去重键 / React key（`Map<offset, line>`），不需要为回放做特殊分支。
  回放帧的 `offset` 一定 `< hello.cursor`；`offset >= hello.cursor` 的行属于
  「回放期间新增」，由实时循环补发，既不会重复也不会丢。
* `hello` 仍然**最后**发（顺序与 1.x 一致，前端不用改解析逻辑）。它是权威续传点：
  断线重连后先 `GET /api/v1/console?since=<上次的 cursor>` 补洞，再连 WS。
* 服务端内部使用的哨兵回显已被过滤，不会出现。

### `POST /api/v1/console/commands`
```json
{ "command": "seed" }
```
→ `{ "ok": true, "command": "seed", "output": "World Seed: 3.3.1.0.1269458679\n" }`

**白名单**：`help save settle playing version port maxplayers time seed motd password
kick ban say dawn noon dusk midnight`。
`exit` / `exit-nosave` 一律 **403**（关服请用 `/api/v1/server/restart`，它会保存并等待恢复）。
每次调用都会记进审计。

### `GET /api/v1/console/audit`
`{entries:[{ts, command, actor}]}`，最近 200 条。

## 5. 配置（持久化 vs 运行时）

### `GET /api/v1/config`
```json
{
  "values": { "motd": "...", "maxplayers": "255", "port": "7777", "world": "gogogo.wld",
              "password": "••••••" },
  "password_set": true,
  "editable_keys": ["autocreate","difficulty","language","maxplayers","motd","npcstream",
                    "password","port","priority","seed","secure","upnp","world","worldname"],
  "runtime_keys": ["maxplayers","motd","password"],
  "restart_keys": ["autocreate","difficulty","language","port","secure","seed","upnp",
                   "world","worldname"],
  "path": "/opt/terraria/config/serverconfig.txt"
}
```

**`password` 不回显明文**：已设置时 `values.password` 是掩码 `••••••`，未设置时是 `""`，
两种情况都用 `password_set` 明确区分。面板应当：

* 密码输入框**留空** + placeholder「留空表示不修改」；
* 只有用户真的输入了内容，才把 `password` 放进 `PUT` 的 body。

### `PUT /api/v1/config`
```json
{ "values": { "motd": "hello", "maxplayers": 255 }, "apply": true }
```

* **总是写进 `serverconfig.txt`**（持久化，重启不丢）；写入是原子的，注释与顺序保留。
* `apply=true` 时，`runtime_keys` 里的项会立刻用控制台命令生效。
* 改到 `restart_keys` 时会**顺带提交一次重启操作**，响应变成 **202**：

```json
{ "persisted": ["port","motd"], "changed": ["port","motd"], "applied": ["motd"],
  "requires_restart": ["port"], "operation_id": "8f3c1a9b2d4e" }
```

* 校验失败 → **400**（`details.editable_keys` 列出允许的键）。
* **`password` 的三态语义**（掩码之后必须写死，别再靠"猜"）：

  | 请求里 | 结果 |
  | --- | --- |
  | 不带 `password` 键 | **不修改**（前端留空时就这样发） |
  | 带非空值（如 `"s3cret"`） | 设为该密码 |
  | 带空字符串 `""` | **400** `bad_request`——不允许通过接口把密码清空（会让服务器直接对公网敞开）。确需清空请改 `serverconfig.txt` 后重启 |
  | 带掩码 `"••••••"` | **400** `bad_request`（`details.key="password"`）——防止把 `GET` 的结果原样 `PUT` 回来 |
* **`maxplayers` 小于 64 需要二次确认**：

  ```json
  { "values": { "maxplayers": 8 } }
  ```
  → **409** `conflict`，
  `error.details = { "requested": 8, "recommended_min": 64, "reason": "phantom-full" }`

  原因见 [`../connection-guard.md`](../connection-guard.md)：原版会把每条陌生 TCP
  连接都算进 `maxplayers`，8 个槽位很容易被扫描流量拖成「假满员」。
  面板应弹确认框，确认后带上 `"confirm_low_max_players": true` 再发一次。

## 6. 世界与备份

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/worlds` | `{worlds:[{file,name,size,modified_at,active}], active_world, backup_dir}` |
| POST | `/api/v1/worlds` | multipart `file=@x.wld` → **201** `{name,file,size}`；同名 **409** |
| DELETE | `/api/v1/worlds/{file}` | 删除；**当前激活的世界不能删** → 409；不存在 → 404 |
| POST | `/api/v1/worlds/{file}/activate` | **202** `{operation_id,...}` |
| POST | `/api/v1/worlds/{file}/backup` | **202**；把该世界（或全部）与 `serverconfig.txt` 复制到 `backup/<时间戳>/` |
| GET | `/api/v1/backups` | `{backups:[{name,created_at,files,size,kind,restorable,path}]}` |
| POST | `/api/v1/backups/{name}/restore` | **202** 从备份恢复整个世界 |

`kind` 有三类：`manual`（面板/定时任务创建的 `20260917-170849`）、
`auto`（Terraria 自己写的 `.wld.bak`/`.bak2`，名字形如 `auto:gogogo.wld.bak`）、
`legacy`（迁移时留下的 `config-*`/`worlds-*`）。

**恢复**（`POST /api/v1/backups/{name}/restore`，body 可带 `{"file": "WSD.wld"}`）：

* 恢复的是**当前激活的世界**时，服务端会重启两次：保存 → 存安全副本 →
  停服 → 覆盖文件 → `exit-nosave` 启动（第二次不保存，否则会把刚恢复的文件覆盖回去）。
  全程约 40~90 秒，用 `operation_id` 看进度。
* 恢复**非激活的世界**只复制文件，不重启。
* 覆盖前会在 `backup/pre-restore-<时间戳>/` 留一份安全副本，结果里返回该路径。
* 多世界备份需要显式指定 `file`，否则 **400** 并返回 `error.details.candidates`。
* 备份名做路径校验，`../` 之类一律拒绝。

## 7. 长任务

任何返回 **202** 的接口都给出了 `operation_id`：

### `GET /api/v1/operations/{id}`
```json
{
  "id": "8f3c1a9b2d4e",
  "kind": "world.activate",
  "state": "running",
  "progress": 65,
  "message": "等待服务端重新监听",
  "created_at": 1789000000.0,
  "started_at": 1789000000.1,
  "finished_at": null,
  "result": null,
  "error": null
}
```
`state`：`pending` → `running` → `succeeded` | `failed`。
建议轮询间隔 500ms~1s，`state` 进入终态就停。`kind`：`server.restart` /
`world.activate` / `world.backup`。

### `GET /api/v1/operations`
最近 50 条（新的在前）。

**互斥**：`server.restart` / `world.activate` / `config.apply` 这几类会动服务端进程，
同一时刻只允许一个；重复提交会得到 **409** `conflict`，`error.details.operation_id`
是正在跑的那个。

> 操作状态存在 API 进程内存里，API 重启即清空（面板遇到 404 就当「已结束、结果未知」处理）。

## 8. 定时任务

配置在 `docker-compose.yml` 的 `SCHEDULE_*`（见仓库根 README 的「定时任务」一节）。

### `GET /api/v1/scheduler`
```json
{
  "enabled": true,
  "timezone": "Asia/Shanghai",
  "jobs": [
    { "name": "save", "kind": "interval", "description": "每 15 分钟保存一次世界",
      "enabled": true, "interval_seconds": 900, "at": null,
      "next_run": 1789637000.0, "last_run": 1789636100.0,
      "last_status": "skipped", "last_detail": "skipped: 无人在线",
      "run_count": 12, "skipped_count": 9, "failed_count": 0,
      "history": [{ "at": 1789636100.0, "status": "skipped",
                    "detail": "skipped: 无人在线", "duration": 0.1, "manual": false }] }
  ]
}
```
`last_status`：`succeeded` | `skipped`（附原因）| `failed`。

### `POST /api/v1/scheduler/{name}/run`
手动触发一次，同步返回本次结果（`save`/`backup` 通常几百毫秒；
`restart` 会返回 `submitted: <operation_id>`，进度仍看 `/api/v1/operations`）。
不存在的任务名 → **404**。

## 9. 事件通知

### `GET /api/v1/notifications`
```json
{
  "enabled": true,
  "url": "https://discord.com/…",
  "format": "auto",
  "events": "all",
  "deliveries": [
    { "ts": 1789636100.0, "event": "player_join", "title": "ユノの犬 加入了游戏",
      "ok": true, "status": 204, "error": null }
  ]
}
```
webhook URL 只回显主机名（它本身就是凭据）。`events` 为 `all` 或事件名列表。

### `POST /api/v1/notifications/test`
同步投递一条测试消息，返回投递结果——配置完 webhook 用它验证最方便。

事件类型：`player_join`、`player_leave`、`player_booted`、`server_up`、`server_error`、
`backup_done`、`schedule_failed`、`restart_skipped`。

`NOTIFY_FORMAT=auto` 会按 URL 识别 **Discord / Slack / 飞书**，都不是则发通用 JSON。
飞书用 `{"msg_type":"text","content":{"text":...}}`；由于飞书 HTTP 状态码恒为 200，
后端会额外解析响应体的 `code`，把它当成真正的投递结果。

## 9.1 连接守卫

守卫（`terraria-guard` 容器）拿着 ipset/NET_ADMIN 权限，API 通过共享的
`control/` 目录与它通信，所以这里的接口都是同步的（内部等守卫确认，约几百毫秒）。

### `GET /api/v1/guard`
```json
{
  "available": true,
  "stale": false,
  "age": 0.2,
  "updated_at": 1789639000.0,
  "port": 7777,
  "allowlist_only": false,
  "allow": [
    { "ip": "198.51.100.30", "source": "static",  "expires_at": null },
    { "ip": "203.0.113.10", "source": "learned", "expires_at": 1790243800.0 }
  ],
  "banned": [ { "ip": "203.0.113.9", "expires_at": 1789642600.0 } ],
  "counters": { "bans_total": 9, "commands_total": 12,
                "learned_total": 2, "degraded_console": 0 }
}
```

* `available: false` 表示守卫容器的状态文件不存在或已过期（>30 秒没更新）。
  接口仍然返回 **200**，面板可以显示「守卫已停止」，不用处理 5xx。
* **`available: false` 时其余字段依然存在**：`allow` / `banned` 是空数组，
  `counters` 是四项全 0 的完整对象。契约上 `GuardState` 与 `GuardCounters`
  的**所有**字段都是必填——客户端不需要写 `guard.allow ?? []` 这类兜底，
  `available` 只用来切换文案。
* `source`：`static` 来自 `guard/allow.txt`，`learned` 是玩家登录后自动加入的。

### 操作

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/guard/bans` | `{"ip": "1.2.3.4", "seconds": 3600}`；`seconds` 省略用默认（1 小时） |
| DELETE | `/api/v1/guard/bans/{ip}` | 解封（同时清掉内部计数，避免立刻被重新封） |
| POST | `/api/v1/guard/allow` | 加入白名单：**写 `guard/allow.txt`** 并立即生效 |
| DELETE | `/api/v1/guard/allow/{ip}` | 移出白名单（静态与学习型都清） |
| POST | `/api/v1/guard/reload` | 按白名单文件重新同步 ipset |

返回 `{"ok": true, "message": "…", "command_id": "…"}`。
守卫没运行时 **503** `guard_unavailable`；IP 格式非法同样 503（消息里说明原因）。

## 10. 旧接口（已删除）

**2.0.0（2026-09-19）起旧 `/api/*` 资源路由全部删除，调用会得到 404**（错误体仍是统一
形状，`code = "not_found"`）。删除前它们带过 `Deprecation` / `Sunset` 头，观察期与
调用量数据见 [`CHANGELOG.md`](CHANGELOG.md) 的 2.0.0「Removed」段。

迁移对照（1.2.0 起就给出了，前端 1.4.0 已完成迁移）：

| 旧 | 新 |
| --- | --- |
| `GET /api/server/status` | `GET /api/v1/server` |
| `GET /api/server/players` | `GET /api/v1/players`（多了 IP/端口） |
| `POST /api/server/{playing,version,port}` | `GET /api/v1/server`（查询不该用 POST） |
| `POST /api/server/{maxplayers,motd,password}` | `PUT /api/v1/config`（可持久化） |
| `POST /api/server/kick\|ban` | `POST /api/v1/players/{name}/kick\|ban` |
| `POST /api/server/say` | `POST /api/v1/broadcast` |
| `POST /api/server/save\|settle` | `POST /api/v1/server/actions` |
| `POST /api/server/time/{phase}` | `POST /api/v1/server/time` |
| `POST /api/server/command` | `POST /api/v1/console/commands`（白名单+审计） |
| `GET /api/server/console` / `WS /ws` | `GET /api/v1/console` / `WS /api/v1/console/stream`（结构化） |
| `GET /api/world/list` | `GET /api/v1/worlds` |
| `POST /api/world/upload` | `POST /api/v1/worlds` |
| `POST /api/world/switch` | `POST /api/v1/worlds/{file}/activate`（202，不再挂 30 秒） |

`GET /api/meta/usage`（弃用调用量统计）也一并删除了：它的用途已经完成。
`GET /api/health` 与 `GET /api/meta` 保留。
